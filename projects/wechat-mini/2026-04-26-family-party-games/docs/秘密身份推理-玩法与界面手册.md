# 秘密身份推理（聚会版）— 玩法与界面手册

> 对应小程序分包页面：`packageGames/werewolf/werewolf`  
> 云函数：`werewolfService`  
> 内部代号：`werewolf`（展示文案已家庭化，无恐怖向用语）

本文按**真实界面区块**和**云阶段**编写：谁在什么阶段看到什么、点哪个按钮、结束后谁还能做什么。

---

## 一、这是什么游戏

- **线下聚会 + 手机辅助**：每人一部手机进同一个「聚会组」，身份只显示在自己屏幕上；**组长（主持）** 一台手机推进流程，**没有自动法官**。
- **口令**：6 位数字，仅邀请身边人进组，无陌生人匹配。
- **人数**：板子为 **6 / 8 / 10 / 12 人局**，指**参与者人数（不含主持）**。主持固定 1 人，不占身份牌。

---

## 二、角色与板子（发牌后）

界面用词（代码 `RZH`）与经典狼人杀的对应关系：

| 界面名称 | 内部角色 | 能力摘要 |
|----------|----------|----------|
| 暗位成员 | werewolf | 夜间在成员列表选「关注对象」；多名暗位时票多者生效 |
| 线索员 | seer | 夜间点一人，弹窗看「倾向：暗位侧 / 村民侧」 |
| 治愈者 | witch | 每局各 1 次：为夜间关注对象「缓解」；或「备用提醒」使一人暂离 |
| 协定者 | hunter | 被投票离场后，可再选一人「同步暂离」 |
| 村民 | villager | 白天发言、投票，无夜间按钮 |

### 各人数身份数量

| 人数 | 暗位 | 线索员 | 治愈者 | 协定者 | 村民 |
|------|------|--------|--------|--------|------|
| 6 | 2 | 1 | 1 | — | 2 |
| 8 | 2 | 1 | 1 | 1 | 3 |
| 10 | 3 | 1 | 1 | 1 | 4 |
| 12 | 4 | 1 | 1 | 1 | 5 |

## 三、怎么进入游戏

### 路径 A：首页直达

1. 首页 → **秘密身份推理（聚会版）**
2. 进入 `werewolf` 页（未进房状态）

### 路径 B：经 setup 创建

1. 首页点该游戏 → `pages/setup/setup?screen=werewolf`
2. 选人数 → **创建聚会组并进入** → 自动跳进 `werewolf` 并带上 `roomId` / 口令

### 路径 C：朋友分享

- 打开分享卡片，带 `roomId` + 6 位口令，自动进房或预填口令。

## 四、页面总布局（进房后）

从上到下大致固定为：

```
┌─────────────────────────────────────┐
│ 标题区：🎭 秘密身份推理 + 阶段·第N天   │  ← 进行中显示「夜间/发言…」
├─────────────────────────────────────┤
│ 聚会组口令（可点复制）+ 【邀请朋友】    │  ← 微信分享按钮
│ 状态横幅（黄/普通）：等人/进行中提示    │
├─────────────────────────────────────┤
│ 成员列表（头像、昵称、👑组长、状态点）  │  ← 选目标时此处高亮可点
│   [选目标时] 提示条 + 确认/取消         │
├─────────────────────────────────────┤
│ 等待中：参与者【准备】条（非组长）      │
│ 已结束：结束文案 + AI 按钮（若开启）    │
│ 等待中：组长人数步进 + 【开始互动】     │
│ 等待中：组员「等待组长…」+ 邀请         │
│ 进行中：本机身份卡 + 公屏日志 + 昨夜     │
│ 进行中：各身份操作卡 + 主持操作卡       │
└─────────────────────────────────────┘
```

弹层（按需出现）：

- **用户信息授权** `user-info-modal`：首次点「准备」可能要头像昵称
- **AI 分享引导** `ai-share-modal`：战报/海报解锁相关

## 五、阶段 0：未进房（`roomId` 为空）

**谁能看到**：任何人打开页面且尚未创建/加入成功。

| 区块 | 内容 | 操作 |
|------|------|------|
| 标题 | 🎭 秘密身份推理 + 副标题说明 | — |
| 昵称 | 输入框 | 输入昵称，失焦会存本地 `werewolf_nick` |
| 本环节人数 | `-` / 数字 / `+` 步进 | 在 **6、8、10、12** 四档切换；下方灰字：`可选 6/8/10/12 人局（不含主持）` |
| 主按钮 | **创建聚会组** | 按当前人数创建；组长即创建者 |
| 已有口令 | 6 位数字输入框 | 仅数字，最多 6 位 |
| 次按钮 | **加入互动组** | 口令不满 6 位会 Toast「请输入 6 位数字口令」 |

**结束后谁干嘛**：此阶段无「局结束」概念；创建/加入成功即进入「已进房」。

## 六、阶段 1：大厅等待（`status: waiting`）

### 6.1 所有人都能看到

| 元素 | 说明 |
|------|------|
| 聚会组口令 | 大号数字；**点击数字区域**复制到剪贴板 |
| **邀请朋友** | `open-type="share"`，发微信卡片带口令 |
| 成员列表 | 每人：头像、昵称、👑（组长）、绿点=准备/在场 |
| 进度条 | 仅等待阶段：当前参与者 / 目标人数 |
| 状态横幅 | 组长：`⏳ 参与者到齐后点「开始互动」发牌`；组员：`👥 等待组长开始互动`；人未满时横幅偏警告色 |

成员行副文案（等待中）：

- 组长行：`组长`
- 其他：`已准备` / `未准备`

### 6.2 组长（主持）额外区块

| 元素 | 按钮/操作 |
|------|-----------|
| 本环节人数 | 同上 `-` / `+`，改完自动云同步 `setSize`（仅 waiting） |
| 测试工具（仅开发开关开启时） | **+ 模拟玩家**、**补齐人数** |
| **开始互动** | 主色大按钮；条件不满足时样式变灰但仍可点，会弹窗说明 |

**开始互动条件（全部满足）**：

1. 你是组长  
2. 参与者（不含组长）人数 **=** 设定的 6/8/10/12  
3. 每一位参与者都已点 **准备**（`profileReady`）

失败弹窗示例：人未满、有人未准备、仅组长可开始等。

### 6.3 参与者（非组长）额外区块

| 元素 | 说明 |
|------|------|
| **准备** / **已准备** | `room-ready-bar` 一条；未准备可点，已准备禁用 |
| 等待卡片 | 文案「等待组长开始互动…」+ **邀请朋友** |

点「准备」：可能先弹出授权头像昵称，再同步云端。

### 6.4 点击「开始互动」之后

- 云端洗牌发身份，`status` → `playing`，`currentPhase` → **`night`（第 1 夜）**
- 公屏日志首条：`第1夜。暗位选择关注对象、线索员查看、治愈者协助。完成后由主持点【结算入昼】。`
- **组长**：界面显示「你本机：主持（无身份）」+ 主持操作区  
- **参与者**：显示「你本机：暗位成员/线索员/…」；暗位另见「同组暗位：昵称列表」

## 七、阶段 2：进行中（`status: playing`）

顶部副标题示例：`夜间 · 第 1 天`（阶段中文：大厅/夜间/天亮了/发言/投票/协定者/结束）。

### 7.1 公共信息区（身份卡下方）

| 区块 | 谁可见 | 内容 |
|------|--------|------|
| 本机身份行 | 全员 | 主持 / 你的角色名 |
| 同组暗位 | 仅暗位成员 | 其他暗位昵称 |
| 本夜线索 | 仅线索员（当晚查过后） | 如「倾向：暗位侧」 |
| 看牌列表 | **仅组长** | 每位参与者真实角色（勿外泄） |
| 公屏日志 | 全员 | 多行文字，阶段推进与出局记录 |
| 昨夜 | 全员 | 上一夜结算摘要 |

成员列表副文案（进行中）：`在场` 或 `暂离`（已出局）。

---

### 7.2 夜间 `currentPhase: night`

**线下建议**：全员闭眼；有夜间能力的人看手机操作；组长最后点结算。

#### 暗位成员（存活）

| 位置 | 按钮 | 行为 |
|------|------|------|
| 「夜间·暗位」卡片 | **在成员列表中选择关注对象** | 进入选目标模式，成员区可点者高亮 |
| 同上 | **取消选择** | 仅 `pickMode === wolf` 时显示 |
| 成员列表 | 点一名参与者 | 弹窗确认 → 提交 `wWolf` |
| 成员区提示 | `👇 点下方成员选择夜间关注对象` | — |

多名暗位：各自投票，云端按票数聚合 `wkill`（平票取其中一个）。

#### 线索员（存活）

| 按钮 | 行为 |
|------|------|
| **在成员列表中查看线索** | 进入选目标模式 |
| **取消** | 退出选目标 |
| 点成员（无需再点确认） | 立即请求 `wSeer`，弹窗「身份倾向：暗位侧/村民侧」 |

不能查自己；不能查已暂离者。

#### 治愈者（存活）

| 按钮 | 出现条件 | 行为 |
|------|----------|------|
| 文案「夜间关注对象已同步」 | 已有 `wkill` | 仅提示 |
| **为关注对象缓解** | 解药未用（`saveLeft`） | 一键 `wWitch` save，抵消当晚该关注对象的暂离 |
| **在成员列表中使用备用提醒** | 毒药未用 | 进入 poison 选目标模式 |
| **取消** | poison 模式中 | 退出 |

毒药流程：点成员 → 成员区上方出现 **确认** / **取消** → 确认后 `wWitch` poison。

#### 组长（主持）

| 按钮 | 行为 |
|------|------|
| **代暗位选关注对象** | 主持代填 `wkill`（成员未操作时补位） |
| **结夜 / 天亮了** | `hostResolveNight`：结算死亡、进入 `day_announce` |
| AI 副主持：开/关 | 可选，阶段切换时自动播报一行 |
| **AI 播报** | 手动触发主持话术 |

**结夜结算规则（云端）**：

1. 取夜间关注对象 `wkill`（或暗位票聚合结果）  
2. 若治愈者已对该对象「缓解」→ 公屏「XXX 已获缓解」，不出局  
3. 否则 → 该参与者 **暂离**（`alive: false`）  
4. 若治愈者用了备用提醒 → 被选者暂离  
5. 清空当夜临时数据，写入「昨夜」摘要，阶段 → **`day_announce`**  
6. 若已满足胜负 → 直接 **`end`**

村民、协定者（夜间）：**无操作按钮**，等待组长结夜。

---

### 7.3 天亮了 `day_announce`

**目的**：宣读昨夜结果，再进入发言。

| 谁 | 界面 | 按钮 |
|----|------|------|
| 组长 | 「主持」卡片 | **进发言** → `hostDawnToSpeak`，阶段变 `speak` |
| 其他人 | 仅公屏/昨夜/成员状态 | 无按钮；口头讨论 |

---

### 7.4 发言 `speak`

| 谁 | 按钮 | 行为 |
|----|------|------|
| 组长 | **下一位发言** | `speakIndex + 1`，公屏追加「下一位发言」 |
| 组长 | **开投票** | 进入 `vote`，`voteOpen: true` |
| 其他人 | — | 按组长主持顺序线下发言；小程序不强制「轮到谁」高亮 |

发言顺序：开局时云端随机 `speakOrder`，组长用「下一位」推进索引（线下可对号入座）。

---

### 7.5 投票 `vote`（且 `voteOpen: true`）

#### 存活参与者（非组长）

| 按钮 | 行为 |
|------|------|
| **在成员列表中投票** | 进入 vote 选目标 |
| **取消** | 退出 |
| 成员区 **确认投票** / **取消** | 确认后 `vote`，Toast「已投票」 |

每人一票，可改投需看是否重复进入（当前实现为写入 `currentVotes[openId]`）。

#### 组长

| 按钮 | 行为 |
|------|------|
| **计票** | `hostResolveVote` |

**计票结果**：

- 得票最高者 **暂离**  
- 若其为 **协定者** → 阶段变 **`hunter`**，`pendingHunter` = 该人  
- 否则 → 直接进入 **`night`**，`day + 1`，重置当夜能力次数（治愈者解药/毒药各重置为 1）  
- 公屏记录「投票离场：XXX」  
- 若胜负已分 → **`end`**

---

### 7.6 协定者环节 `hunter`

**仅**被投票出局的协定者本人（且存活标记刚变 false 后进入此阶段）：

| 按钮 | 行为 |
|------|------|
| **在成员列表中选择** | 选一人 |
| **确认** / **取消** | 确认 → `hunterShot`，被选者暂离 |
| 公屏 | 「协定者邀请 XXX 同步暂离」 |

完成后：阶段 → **`night`**，天数 +1，开启新一夜。

组长在此阶段：**无**「计票」类按钮，等协定者点完或线下催促。

---

### 7.7 阶段循环简图

```
night → [组长: 结夜/天亮了] → day_announce → [组长: 进发言] → speak
  → [组长: 开投票] → vote → [存活者投票] → [组长: 计票]
       → (若出局者为协定者) hunter → [协定者选人] → night（day+1）
       → (否则) night（day+1）
  … 重复直至 end …
```

## 八、阶段 3：结束（`status: ended` 或 `currentPhase: end`）

### 8.1 所有人共同看到的结束卡片

| 元素 | 内容 |
|------|------|
| 标题 | **本环节结束** |
| 副文案 | `村民侧` 或 `暗位侧` + 「本环节收束」+ `gameEnd` 原因文案 |

胜负条件（云端 `checkWin`）：

| 结果 | 条件 | 展示侧 |
|------|------|--------|
| 村民侧胜 | 所有暗位均已暂离 | `winSide: good` |
| 暗位侧胜 | 存活暗位人数 ≥ 存活村民侧人数 | `winSide: wolf` |

### 8.2 结束后各角色能做什么

| 角色 | 还能点的按钮 | 说明 |
|------|--------------|------|
| **所有人** | **邀请朋友**（口令区仍在） | 可分享，但局已结束，新进房需新组 |
| **所有人** | 复制口令 | 仍可点数字复制 |
| **所有人**（功能开关开启） | **AI 战报文案** | 需解锁等级 `canRecap`；未解锁显示锁定样式 |
| **所有人**（功能开关开启） | **生成海报** | 同上 |
| 主持操作区 | **消失** | `playing` 且非 end 才显示 |
| 身份操作区 | **消失** | 同上 |
| 准备条 | **消失** | 仅 waiting |
| 开始互动 | **消失** | 仅 waiting |

**结束后不会自动开新局**：需组长重新创建聚会组，或大家退出后用新口令（当前房间 `status: ended`）。

### 8.3 AI 战报 / 海报之后

- 战报：弹层展示 AI 生成短文（约 200 字内）  
- 海报：走海报生成流程；可能弹出 **分享解锁** 引导（`ai-share-modal`）  
- 与对局逻辑无关，纯纪念/分享

## 九、成员列表「点选模式」统一说明

进入任选一目标的操作后，**同一成员列表**会变成选择器：

| 模式 | 谁可进 | 点成员后 | 成员区额外按钮 |
|------|--------|----------|----------------|
| wolf | 暗位 | 确认弹窗 | 无（确认在弹窗） |
| hostWolf | 组长代选 | 确认弹窗 | 无 |
| seer | 线索员 | 立即查 | 无 |
| poison | 治愈者 | 仅选中高亮 | **确认** / **取消** |
| vote | 存活参与者 | 仅选中 | **确认投票** / **取消** |
| hunter | 协定者本人 | 仅选中 | **确认** / **取消** |

可选目标规则：排除组长、排除自己（代选除外）、排除已暂离。

顶部黄色提示条示例：`👇 点成员后确认投票`。

## 十一、常见误区

| 误解 | 实际 |
|------|------|
| 组长算进 6 人局 | **6 人局 = 6 名参与者 + 1 名组长**，共 7 台手机 |
| 人齐自动开局 | 须组长点 **开始互动**，且全员 **准备** |
| 小程序当法官 | **组长手动** 结夜、进发言、开投票、计票 |
| 身份会显示给别人 | 仅本机 `getView`；组长有「看牌」列表，勿投屏 |
| 结束后同房间再来一局 | 需 **新建聚会组**（本房已 ended） |
| 投票平票 | 当前实现取得票最高者；无人投票则计票可能无出局 |
