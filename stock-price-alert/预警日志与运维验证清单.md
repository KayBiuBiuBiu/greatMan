# 预警日志与运维验证清单

本文整理「验证预警写入 → 核对成本 → 回测打样 → 定时任务 → 观察反馈 → 体验记录」的可执行步骤；与 `config.json` 中 **`kline_store.db_path`**（您当前为绝对路径）及 **`alert_log.share_kline_db`** 一致时，`alert_events` 落在**同一 SQLite 文件**中。

---

## 一、验证预警日志是否正常写入（约 5 分钟）

### 1. 确保配置已开启

打开 `config.json`，确认存在（或与下面等价）：

```json
"alert_log": {
  "enabled": true,
  "share_kline_db": true,
  "db_path": "data/alert_events.db",
  "bearish_hit_threshold_pct_1d": -2,
  "bearish_hit_threshold_pct_3d": -2.5,
  "bearish_hit_threshold_pct_5d": -3
}
```

若缺失可参考 `config.example.json`。**`share_kline_db: true`** 时，实际使用的库路径与 **`kline_store.db_path`** 相同（您环境中为 `.../data/daily_klines.db`），`db_path` 仅在不共享时使用。

### 2. 跑一轮监控以触发写入

- **盘中**：正常 `run_alert` 即可；触发通知类预警时会写入（见下条「注意」）。
- **调试**：`python run_alert.py -c config.json --once` 等；若加 **`--no-notify`**，则**趋势 / 策略 / 止盈止损 / 下跌预警**不会发通知也**不会写入**这些类型的 `alert_events`；**区间价**在触发时仍会写入。要验证全类写入，请至少一轮**不带** `--no-notify`。

### 3. 查询 `alert_events` 行数

请将下面路径换成您 `config.json` 里 **`kline_store.db_path`** 的实际值：

```bash
sqlite3 /Users/haha/greatMan/stock-price-alert/data/daily_klines.db "SELECT COUNT(*) FROM alert_events;"
```

- **首次**：若尚未有任何写入，可能尚未建表；跑过一次带 `init_schema` 的路径（如 `backtest_alerts.py` 或监控写入）后表即存在。
- **`COUNT(*) > 0`**：说明已有成功写入。

### 4. 抽查最近几条（可选）

```bash
sqlite3 /path/to/daily_klines.db "SELECT id, fired_iso, code, alert_type, eval_status FROM alert_events ORDER BY id DESC LIMIT 5;"
```

## 二、核对持仓成本与配置（避免风控误判）

您已将持仓写入 `watchlist`，建议定期：

1. **逐只对比** `cost_price`、`hold_shares` 与券商「成本价」「持股数量」。
2. **除权、分红送配**后若券商已摊薄成本，请同步改配置。
3. 若成本与真实值偏差 **超过约 1%**，`drawdown_alert`、止盈止损的盈亏与档位会偏离实际，建议修正。

示例：绿发电力成本 **10.2504**，配置写成 **10.25** 一般可忽略；写成 **10.0** 则建议改掉。

## 四、定时任务（日 K 同步 + 指标预计算）

`sync_daily_klines.py` 默认会同步 **`watchlist` + `daily_picks.json` 优质股**（与盘中优质池一致）；若只想同步 watchlist，加 **`--skip-daily-picks`**。

A 股日盘 **15:00** 收盘，宜在 **15:05 之后**（或您习惯的盘后窗口）再拉日 K，避免数据未齐。以下为示例 crontab（**请按本机路径与 Python 解释器调整**）：

```bash
crontab -e
```

示例（工作日、先确保 `logs/` 目录存在）：

```cron
# 日 K 同步（示例：每个交易日 15:10）
10 15 * * 1-5 cd /Users/haha/greatMan/stock-price-alert && /usr/bin/python3 sync_daily_klines.py >> logs/sync.log 2>&1

# 指标预计算（接在同步之后，示例 15:18）
18 15 * * 1-5 cd /Users/haha/greatMan/stock-price-alert && /usr/bin/python3 compute_kline_indicators.py >> logs/compute_indicators.log 2>&1
```

若坚持使用 **15:30 / 15:35**，在多数交易日也可行；若遇数据延迟，可适当后移。`python` 建议写**绝对路径**（`which python3`）。
