# 系统运行说明（当前实现）

主入口是 **`run_alert.py`**。下面按「你平常会怎么跑」和「进程里在干什么」说明；筛选公式见 **[筛选与判断逻辑.md](./筛选与判断逻辑.md)**，分数与信号细节见 **[评分与买卖信号说明.md](./评分与买卖信号说明.md)**。

---

## 1. 你怎么启动它

| 命令 | 行为 |
|------|------|
| `python run_alert.py` | **默认主流程**：先自动跑一遍 **盘前选股+回测**（写 `daily_picks.json`），再进入 **无限轮询监控**。 |
| `python run_alert.py --scan` | 只做 **全市场分层扫描**，更新 `config.json` 里的 `watchlist`（受扫描间隔约束，可加 `--force-scan`）。 |
| `python run_alert.py --daily-select` | 只做 **盘前选股**，写 `daily_picks.json`，然后 **退出**。 |
| `python run_alert.py --daily-auto` | 先选股，再 **进入监控**（与默认类似，但语义上强调「一键」）。 |
| `python run_alert.py --once` | 监控主循环里 **只跑一轮** 就退出（调试用）。 |
| `python run_alert.py --no-notify` | 不发 **系统通知**，也 **不发邮件**。 |
| `python run_alert.py --poll-when-closed` | 休市也 **请求行情**（默认仅交易时段请求，省流量）。 |
| `python run_alert.py --backtest-code 600000` | 单票回测，写 `backtest_report.json` 后退出。 |
| `python run_alert.py --test-notify` | 测一条 Mac 通知后退出。 |

配置默认读 **`config.json`**（可用 `-c path` 指定）。

---

## 2. 默认主流程启动时先后做什么

1. **（若走默认）** `_run_auto_daily_select`：用 `quant_core/selector.run_daily_selector` 拉全市场列表前 N 只（`scan_pool_max`，上限 800），算因子分 + 1/3/5 年简化回测，分 **优质/观察/淘汰**，结果写入 **`daily_picks.json`**。若某步失败会返回非 0 并退出。
2. **读入并合并配置** `merge_full_config`：把 `poll_interval_seconds`、`trading_closed_interval`、`scan_rule`、`capital` 等缺省补全。
3. **风控对象** `RiskManager(cfg)`：后面止盈止损、补仓、仓位都靠它。
4. **状态** `.alert_state.json`（与 config 同目录下的 `state_path`）：冷却、区间提醒上次触发等；启动时 `load_state`，并从 state **hydrate** `hold`/`sell` 对应的强制纳入/剔除代码集合。
5. **后台 stdin 线程**：你在终端输入 **`hold` / `unhold` / `showhold` / `sell`** 会进队列，每轮循环开头处理。
6. **组装本轮监控列表 `watch`**：见下一节。

---

## 3. 每一轮「监控谁」：`watch` 怎么来的

函数 **`_build_watch_from_daily_picks_with_overrides`**：

- **基础**：`config.json` 里的 **`watchlist`**（`enabled` 为真的条目）。
- **若存在 `daily_picks.json` 且能读出「优质股」代码集合**（`_load_quality_codes`）  
  - 模式 **`quality_only`**：盘中 **主要只监控这些优质代码**；在 `watchlist` 里找不到的会临时造一条占位规则。  
  - **`hold` 强制的代码**（`force_include_codes`）会 **并入**，即使不在优质池。  
  - **`watchlist` 里带持仓标签** 的标的，若不在优质池里，也会 **追加保留**（避免漏看真持仓）。
- **若没有优质股清单**（文件缺失或为空）  
  - 模式 **`fallback_all`**：**整份 `watchlist`** 都监控，再叠加上面说的 `hold`/`sell` 运行时覆盖（`_apply_runtime_watch_overrides`）。

终端会打印 `[AI筛选] 盘中仅监控 daily_picks…` 或 `回退监控全部 watchlist`。

## 4. 主循环里每一轮做什么（核心）

大致顺序（`while True` 内）：

1. **清空命令队列**：执行 `_handle_runtime_command`（可能改 `config.json`、`force_include_*`）。
2. **重新 `watch`**：config 或 `daily_picks` 更新后，下一轮列表会跟着变。
3. **若开启「仅交易时段请求行情」** 且当前非交易时段：打印休市提示，`sleep(trading_closed_interval)`，**不拉行情**，继续下一轮。
4. **否则**：`sleep(poll_interval_seconds + 小随机)`（首轮不 sleep），打印 `===== 轮询 … =====`。
5. **大盘情绪**：`fetch_index_mood_mult()`，后面算 `macro_score_multiplier` 用。
6. **对 `watch` 里每条规则**  
   - 东财拉 **报价**（失败时对「持仓/hold 钉住」的标的仍保留占位，标记 `no_quote`）。  
   - 有行情则拉 **K 线**（`get_stock_kline_data`），算 **`composite_pick_score`**（用于排序与「优选画像」卡片，**不参与**是否买卖的最终下单）。  
   - 把结果放进 `items`（含 `sort_score`、`tagged` 等）。
7. **分组展示**  
   - **带标签或 hold 钉住** → 区块 **「我的持仓（带标签）」**。  
   - 其余按 `sort_score` 排序，取前 **`daily_pick_count`**（默认 6）→ **「今日 N 只低吸优选」**（`show_pick_card=True` 时打印优选画像）。  
   - 剩下的 → **「其余监控标的」**。
8. **对每组里每个 pack** 调 **`process_watch_pack`**：打印现价、标签、盈亏、策略行 **`ma_box_strategy`**、止盈止损、补仓、区间价提醒；满足冷却且未 `--no-notify` 时发 **Mac 通知**；买入/卖出时按规则发 **邮件**（卖出邮件需 `hold_shares>0`）。  
9. **写回 state**（含 `force_include`/`force_exclude` 便于下次 hydrate）。  
10. 若本轮失败请求过多，**熔断**多等 `FUSE_MIN_INTERVAL` 秒。  
11. 打印 **总仓位** 提示（若有）。  
12. `--once` 则 `break` 退出循环。

## 5. 和主循环并列的其它模块

| 模块 | 作用 |
|------|------|
| **`stock_scanner.py`** | 定期把东财全市场 → 分层规则 → 写入 **`watchlist`**；与 `run_alert` 主循环 **独立**，通常 `run_alert.py --scan` 或定时任务调用。 |
| **`email_notify.py` + `mail_config.json`** | 买入/卖出邮件；**本地 json**，勿提交 git。 |
| **`notify_macos.py`** | macOS 通知。 |
| **`trade_log.py`** | 策略信号落盘日志。 |
| **名称** | `a_share_names.json` → 缓存 → 必要时 akshare 补一条（`get_stock_name`）。 |

---

## 6. 典型日常使用顺序（建议）

1. 定期或按需：`python run_alert.py --scan`（更新大池子 `watchlist`）。  
2. 盘前或开机：`python run_alert.py`（自动写 `daily_picks.json` 再监控），或先 `--daily-select` 再手动开监控。  
3. 交易时段保持进程运行；改持仓用终端 **`hold` / `unhold`**。  
4. 改轮询间隔、冷却、本金风控等 → 编辑 **`config.json`** 后 **重启** `run_alert`。
